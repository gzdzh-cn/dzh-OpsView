# 全站首次加载与重新登录整改

基于 v0.1.4，验证日期为 2026-11-22。本次修改仅涉及前端读取与展示状态，不新增后端接口或数据库迁移。

## 行为约定

- 无有效数据时，页面第一帧显示公共加载状态，标签与必要工具栏保持可见；只有成功返回后才展示安装引导、空列表或设置值。
- 共享数据区分未读取、加载中、成功和失败，同时单独记录是否已有有效数据。成功的空数组也是有效数据，不能以数组长度决定是否加载过。
- 已有会话缓存继续即时展示；后台刷新失败保留内容并显示错误。首次失败停止转圈，提供重试，不将失败解释为未安装或没有记录。
- 登录后的页面请求由认证状态变化同步启动，复用登录流程已核实的会话；主题与偏好不阻塞业务数据。
- 退出时先停止页面读取，再清理缓存与导航筛选；页面按会话代次重新挂载。旧请求、旧会话检查与旧组件不能回写新会话，也不能因清理筛选而重新发起读取。
- 文件路径栏、操作栏保留在加载内容之外；设置与访问配置独立读取。网站、数据库、Docker、插件市场、备份、系统、设置及任务页统一处理首次读取与失败；网站设置中的独立读取分区同样接入。

## 验证方法

```bash
cd web && npm test
cd .. && make assets
cd web && OPSVIEW_E2E_PORT=18891 npm run test:e2e
```

单元测试覆盖成功空数据、失败重试、缓存保留、请求合并、读取互不阻塞、过期结果丢弃，以及退出后不再订阅读取。

浏览器回归使用生产前端资源和本地 Go 后端。故障分支通过拦截接口构造；网站重新登录测试把资源接口至少延迟两秒，另行延迟认证及阻塞偏好接口，记录首帧状态并监测是否出现错误的 Nginx 安装提示。覆盖十个侧栏页面、真实空结果、失败重试、缓存切页、移动端亮暗主题、SSH 与通知读取失败。

性能统计区分框架出现到局部加载提示的时间、缓存切页时间、认证等待与首次网络下载；本机结果不代表实际服务器网络耗时。

## 验证结果

- 前端单元测试：8 个测试文件、35 项测试通过。
- 类型检查与生产构建：`make assets` 通过；浏览器使用这份生产资源。
- 完整 Playwright：4 个测试文件、83 项测试通过（包含新增的 8 项加载回归）。
- 两秒资源延迟及偏好接口阻塞下，同一路由重新登录首帧即显示加载，无 Nginx 安装提示闪现；登录后仅一次会话核验。
- 十个侧栏页面在框架出现后 200ms 内显示局部加载提示；缓存切页 20 个样本的 P95 为 69.1ms。
- 亮暗主题、移动导航、页面资源失败、后台刷新失败、真实空数据及重试检查通过；原有固定弹窗、文件操作、网站创建与删除、安全入口和 HTTP 登录回归通过。
- 已检查桌面加载截图及移动端深色加载截图，标签位置与内容区域正常；`git diff --check` 通过。

## 发布约定

本次代码整改不覆盖 v0.1.4 的标签或资产。本次发布采用 v0.1.5；公开安装和线上升级的最终结果另记于 v0.1.5 验收记录。
