# 卸载与数据保留

以 root 执行 `ov uninstall`，或在两列菜单选择 **18. 卸载 OpsView**。菜单原有编号保持不变。命令先核对本机登记、服务、容器、路径和挂载点，再展示实际清单。

确认提示为：

```text
确认卸载 OpsView？输入 y 继续，其他输入取消：
```

只有完整输入小写 `y` 并回车才执行。`Y`、`yes`、空输入、EOF 或确认前按 Ctrl+C 均取消。只确认一次，不支持 `--yes`。成功后退出终端菜单，失败返回非零退出码。

## 删除和保留范围

| 项目 | 处理 |
| --- | --- |
| 面板、执行器、插件工作进程、打包工具、受控安装脚本 | 删除安装程序及对应服务、命令链接 |
| 已登记的 Nginx、PHP、MySQL、PostgreSQL、Redis、Node.js | 停止并移除受管服务与运行文件 |
| 网站独立 FPM、托管应用及正在执行的脚本 | 停止进程及其服务；保留应用工作目录 |
| 项目源码、软件编译 `source`、Git 源码目录 | 原路径保留 |
| 网站目录、上传文件、旧版 `sites/<ID>/www` | 原路径、权限及所有权保留 |
| 数据库数据目录及迁移产生的 `data-*` | 保留，包括数据库内部 WAL、事务日志及恢复文件 |
| 面板 SQLite、密钥、证书、设置、计划及审计 | 删除；不会留下可登录的旧面板 |
| 本地备份、更新快照、安装缓存、面板与软件普通日志 | 删除可确认归属的内容；源码和数据保留项优先 |
| OpsView 容器 | 以资源登记和管理标签共同确认归属，只删除对应容器 |
| Docker 卷、其他容器、共享镜像和网络 | 保留，不执行 prune 或删除卷 |
| Docker 引擎、系统依赖包、数据所有者账号 | 保留，不执行 autoremove 或删用户 |
| SSH 设置、普通系统防火墙规则 | 保留，不重置系统配置 |
| OpsView 地区、转发、Ping 扩展及两个防护 jail | 通过原适配层撤销受管扩展，移除受管辅助文件和服务 |
| 远端备份、无法确认归属的文件 | 不自动删除；本地未知备份文件列为保留项 |

源码指项目代码和编译源码。下载的发布归档、编译产物、软件运行二进制不属于保留源码。安装时由用户自行下载到任意目录的脚本或压缩包无法可靠确认归属，不全盘搜索删除。

数据库停止会执行正常终止并等待退出；停止超时或异常退出时，中止卸载，不强行删除数据库服务程序。容器数据库同样不通过强制删除结束进程。

数据保留不包含面板保存的数据库密码、加密主密钥或原软件运行配置。重新使用保留数据时，需要匹配的软件版本并重新建立配置；原数据库内部的账号和认证信息随数据库数据保留。远端加密备份继续需要其原始独立密钥，删除本机密钥不会使远端备份自动变为可恢复。需要的信息应在卸载前自行保存。

## 预检与失败继续

- 安装、更新与卸载共用 `/run/lock/opsview-install.lock`，同一时间只执行一个维护操作。
- 安全设置仍在等待确认或回退时，先完成相应事务再卸载。
- 服务存在自定义 drop-in、程序路径不匹配、登记损坏、未知受管容器或清理范围含挂载点时，预检给出具体原因，不能通过卸载绕过核对。
- 清理不跟随符号链接；保留数据中的链接目标也纳入保护。路径被替换时停止，不对新路径重放删除。
- 进行破坏性清理前保存 root 私有进度到 `/var/lib/opsview/uninstall-progress.json`，不保存资源密码或脚本正文。失败输出已完成步骤和未完成原因，保留继续处理所需程序；修复后重新执行 `ov uninstall`，重新核对并确认。
- 已删除的容器和目录不重复处理；外部替换对象不按旧记录强行删除。成功后删除进度及最后的面板可执行文件。

卸载不是恢复操作，不会自动重新安装软件或恢复被删除的面板配置。

## 开发验证

```bash
cd server
go test -race ./internal/maintenance ./internal/security ./internal/executor
go vet ./internal/maintenance ./internal/security ./internal/executor
cd ..
bash scripts/test-uninstall.sh
```

最后一项仅在脚本新建的临时 Docker/systemd 主机执行真实卸载；不挂载宿主机 Docker Socket，也不接触线上服务器。测试使用实际构建的 CLI、MySQL/PostgreSQL/Redis 进程及独立 Docker 守护进程，检查菜单、取消、维护锁、容器归属、保留数据重新启动和退出行为。宿主机为 ARM 时测试 ARM 构建，正式发布仍沿用 Linux amd64。

### 本次验证记录（2026-11-21）

- Go 全量测试、maintenance/security/executor 的 race 检查及全量 `go vet` 通过。
- 在临时 Ubuntu 24.04 ARM64 主机中通过实际 CLI/systemd 卸载：小写确认、取消、维护锁、中断重试、网站进程停止、服务及程序清理均通过。
- MySQL 8.0、PostgreSQL 16、Redis 7 的数据保留后重新启动，并读取预先写入的测试记录；网站文件及数据目录的 UID、GID、权限保持一致。
- 删除受管 Redis 容器后，其数据卷及外部 Redis 容器保留；原有 SSH 配置和独立 iptables 规则保持不变。
- 原生数据库在测试主机内通过受管实例路径启动，底层使用该隔离主机的软件包二进制。单元测试另覆盖部分安装、异常停止、路径交叠、链接替换、挂载边界和损坏进度。

新增 CI 会运行相同隔离验收；本次本地记录不代表所有发行版、架构和数据库版本均已验证。线上服务器未执行卸载。
