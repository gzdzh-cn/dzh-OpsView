# 系统防火墙与 SSH 管理

本次参考已安装宝塔的可读模块，核对其功能字段、页面动作和配置流程，再以 OpsView 的 Go 执行器及 Vue 组件独立实现。参考过程只读取程序和系统状态，没有修改参考服务器的防火墙、SSH 服务、账号或业务数据，也不包含宝塔程序、付费模块或其授权机制。

## 防火墙能力与入口

进入“系统与安全 → 系统防火墙”自动读取系统配置，不需要检测、导入或同步才能看见已有规则。普通规则直接修改和删除，高级条件不能无损表达时显示原文及只读原因。UFW 读取 user.rules/user6.rules 和内核运行规则；firewalld 同时读取运行与永久配置，保留区域归属、临时规则及服务附件。

| 标签 | 管理能力 |
| --- | --- |
| 端口规则 | TCP、UDP、TCP+UDP；单端口、列表、范围；入站/出站、放行/阻止、来源及目标限制 |
| IP规则 | 单 IP/CIDR、IPv4/IPv6、入站/出站、策略及备注 |
| 端口转发 | 本机 REDIRECT 或同地址族远程 DNAT、等长范围、来源限制及显式 MASQUERADE |
| 地区规则 | IPdeny 国家/地区 CIDR、全部或指定端口、独立 IPv4/IPv6、更新时间 |

四类规则均支持搜索、分页、勾选删除。无原始创建时间显示 `—`，监听状态仅表示本机监听。关闭时仍展示已保存规则并标记未生效；禁 Ping 只阻止 Echo Request，不阻止 IPv6 邻居发现和路径 MTU 通信。原生 firewalld 双栈服务附件保留双栈语义，编辑普通双栈端口会明确拆为 IPv4、IPv6 两条。

UFW 与 firewalld 同时运行时仅诊断，不自动替换。无法表达的自定义条件和数据库授权关联规则不能从通用弹窗修改，后者须从数据库权限入口处理。保留 Docker 与外部链；关闭面板管理的防火墙不代表其他软件的独立过滤同时关闭，云安全组仍需单独配置。

## 确认、冲突与回退

所有网络安全变更由执行器串行处理，端口、SSH、数据库授权和规则管理共同使用适配层。规则具有稳定不透明标识和内容修订；执行前重新读取并匹配，外部变化返回 `409`，不会仅凭旧 UFW 行号删除。耗时操作进入任务中心，支持日志和失败诊断。

涉及实际 SSH/面板端口或管理来源时，填写覆盖真实管理客户端的 IP/CIDR，明确确认影响。执行器先记录回退计划，再增加该来源的管理端口保护，变更后留足 120 秒重新连接确认；未确认自动撤销本次修改。确认前保持原 SSH 会话并从独立终端验证新连接。普通规则不要求无关的重连步骤。

开关同时处理运行及持久化，保留原规则。关闭时暂停 OpsView 地区规则、转发和 `opsview-*` Fail2ban 防护，重新开启后恢复。回退只撤销本次变更，外部漂移无法确认归属时保留现场并报告冲突。

**firewalld 安全限制：**初始化地址集合或首次出站策略可能需要 reload。只在运行与永久配置一致时执行；发现外部 iptables 链（包括 Docker 链和旧版 firewalld 的 iptables 后端）时拒绝重载或启停，避免旧 firewalld 清空外部链。已有普通规则仍可逐项管理。需要初始化扩展的环境应在本机维护窗口由管理员核对，不能以“同步”强制覆盖外部临时配置。

本机 root 命令：

```bash
ov firewall status
ov firewall rollback
# 非交互恢复时显式确认
ov firewall rollback --yes
```

命令只恢复当前 OpsView 防火墙事务，不重置全机规则。回退失败时保留受保护记录，用原 SSH 会话或云控制台核对原因；不要删除 pending 文件绕过保护。执行器重启会继续恢复未完成事务。

## 转发、地区数据与防护

远程转发会启用对应地址族的 IP forwarding，并写入独立 sysctl 配置；删除最后一条规则不会擅自关闭系统全局转发。不开启 MASQUERADE 时目标主机需要有返回路由。UFW 的源转换限制到本条来源和映射端口；firewalld rich MASQUERADE 限制到来源/目标主机，可能作用于同两端之间的其他流量，勾选前需核对。删除只移除目标规则，不清空 NAT 表。

地区数据来自 IPdeny 的 IPv4/IPv6 aggregated CIDR，安装目录保存来源、摘要及原始 Copyrights.txt。面板每小时检查，数据满七天后通过任务中心更新；可手动更新。下载限速、验证 CIDR 后使用版本化集合切换，失败保留原有效策略。允许某地区只是增加允许条件，不自动阻止其他地区；结果仍取决于规则顺序、区域及外部链。旧集合保留供回退，不以下载成功代替实际规则应用成功。

“端口防扫描”是 **Fail2ban 服务异常访问防护**，不宣称识别所有网络扫描。首批 SSH 和 Nginx HTTP 认证失败，需有真实服务及日志来源；未安装时通过任务安装。默认统计 300 秒内失败 30 次，封禁 600 秒；首次开启要求填写覆盖管理来源的白名单。仅维护 `opsview-*` jail，不覆盖其他配置；可查看封禁和解封。

## 导入、导出与同步

支持 OpsView v1 JSON、宝塔常见 JSON、逐行 JSON 和 `|` 分隔记录；预览显示重复、冲突、不支持条件，选择后应用，不能静默忽略未知字段或动态域名条件。高级只读记录和服务附件不能被转换成含义不同的普通规则。导出可选当前类别、已勾选或全部类别，不包含凭据。

同步展示系统与观察记录差异，默认从系统更新面板；恢复历史规则必须逐项选择。同步不会重建整套系统规则，也不会自动重载 firewalld。列表以系统实际配置为准。

## 接口与元数据

`GET /api/v1/system/firewall` 自动读取状态；`POST /api/v1/system/firewall/{action}` 提供保存、删除、导入预览/应用、导出、同步预览/记录/恢复、地区更新、防护设置及确认/回退。认证、CSRF、审计和任务 SSE 沿用现有机制，敏感读取设置 `Cache-Control: no-store`。OpenAPI 包含结构和版本。

rc.11 将 SQLite 增量升级为 schema 4，新增加密防火墙观察映射，保留管理员、业务资源和数据库规则关联 ID。执行器 `firewall-admin/` 保存受保护的事务、扩展、备注和地区数据，待恢复事务存在时更新器拒绝更新。升级和旧版元数据恢复见 [运维说明](operations.md#rc11-系统防火墙更新与回退)。

## 使用 SSH 设置

1. 保留当前 SSH 会话，在“系统与安全 → SSH 管理 → 连接设置”读取实际配置。
2. 修改端口与认证设置；UFW 已启用时填写实际 SSH 客户端来源 IP/CIDR，并在云安全组放行新端口。
3. 提交“校验并应用”。操作进入任务中心，依次检查修订、端口、候选配置和有效配置，再重载并检查 SSH 协议。
4. 在另一个终端用新端口和预期认证方式完成 SSH 登录；成功后在面板明确确认。确认是管理员对实际登录结果的声明，浏览器连接不能证明 SSH 可用。
5. 确认前旧 SSH 端口临时保留；确认后移除旧监听端口，旧 UFW 规则保留。120 秒未确认则恢复原主配置并重载，撤回本次增加的放行规则。

不能同时关闭密码和公钥认证。`root=prohibit-password` 不允许 root 密码登录，即使全局密码认证开启。改为禁止 root 前需先验证其他管理员账号。页面展示及修改的是全局基线，`Match`、PAM、AllowUsers、外部认证及账号状态仍会影响实际登录。

主配置增加独立受管区域，保留注释、未管理字段、Include 和 Match 块。提交检查主配置、Include 内容及全局有效配置修订；外部修改时拒绝覆盖。Include 带来的额外端口或不兼容有效参数会阻止应用。socket 激活、自定义启动端口/配置参数和 SSHD_OPTS 覆盖仅提供诊断。仅监听特定非本机地址的实例无法通过 loopback 协议检查，需在主机管理。

## 公钥与日志

公钥操作仅管理 root 的标准 `.ssh/authorized_keys`，只显示 SHA-256 指纹等元信息，不读取或返回私钥。自定义 AuthorizedKeysFile 或 AuthorizedKeysCommand 不自动接管；备用公钥文件与其他用户不在列表范围。

导入只接受一行 OpenSSH 公钥，不接受私钥、命令选项或多行内容，支持 Ed25519、ECDSA 及至少 3072 位 RSA；重复指纹拒绝添加。删除需确认且不能删除最后一个 root 公钥。已有带选项的条目原样保留；是否可登录仍需使用目标账号实际验证。

日志来自 `journalctl _COMM=sshd`，最多读取近 24 小时的 200 行，不宣称完整登录统计。终端会话来自 `who -u`，不包含所有非交互 SSH 连接。fail2ban 未安装、jail 未启动或不可读时明确显示诊断。

## 恢复与验证

变更记录位于执行器受保护目录下的 `ssh-pending.json` 和 `firewall-mode.json`，权限 `0600`。执行器重启后继续检查截止时间；恢复失败保留记录、显示错误并重试。SSH 主配置被外部修改时，回退前将当前内容保留至 `ssh-conflict.conf` 供核对，不覆盖或恢复管理员在 Include 文件内做的修改。如果 Include 导致旧配置也无法通过校验，需通过保留的 SSH 会话或云控制台手动恢复。

rc.10 不涉及 SQLite 迁移；rc.11 增量升级 schema 4，不修改管理员与现有业务实例。所有新增接口沿用会话认证与 CSRF，系统变更共享任务队列锁，执行器再次校验操作白名单。安全读取接口返回 `Cache-Control: no-store`，会话内仅缓存配置元数据及公钥指纹。

自动验证包括 Go 防注入、冲突、端口占用、确认与持久化回退、公钥保护及接口认证测试，Playwright 的按需加载与确认交互，以及 `bash scripts/test-security-linux.sh` 的独立 Linux 容器测试。容器中使用真实 OpenSSH、公钥登录、旧/新端口切换、回退和 UFW 启停，网络命名空间与宿主机隔离，不挂载 Docker Socket 或宿主机系统目录。
