# 网站创建与管理

## 添加网站

网站菜单保留 PHP 项目、反向代理、其他项目三个标签。安装原生 Nginx 后，点击当前标签的添加按钮。

- **PHP 项目**：每行填写一个域名，选择已安装 PHP 版本或静态，确认根目录和备注。PHP 站使用独立 FPM 服务及非 root 用户，Nginx 自动绑定。
- **反向代理**：填写域名、HTTP/HTTPS 目标及发送 Host。Host 可用 `$host`、`$http_host`、`$proxy_host` 或指定域名；创建后的反向代理设置支持多上游、路径、WebSocket 和超时。
- **其他项目 / 托管应用**：先安装运行时或上传可执行构建产物，选择执行文件和 JSON 参数，例如 `/usr/bin/node` 配合 `["server.js"]`。工作目录为项目根目录。默认创建独立用户，也可选择 www-data；不使用 root 或面板用户、不通过 Shell 拼接执行命令。
- **PHP 项目 / 静态网站**：PHP 版本选择静态，部署 HTML/CSS/JS；创建后设置运行子目录、默认文档及显式 SPA 回退。

输入首个域名会生成项目名称及默认建站目录下的项目文件夹，默认是 `/www/wwwroot/域名`；修改名称或根目录后继续输入域名不会覆盖手动值。可在面板设置中指定其他安全的默认建站目录，站点必须使用其中的独立文件夹；不允许系统及私有目录、链接、目录跳转或两个站点共用目录。域名使用 ASCII/Punycode，不附协议或路径。默认端口来自唯一受管 Nginx，rc.30 起可用 `example.com:8080`、`[IPv6]:8080` 指定 HTTP 端口；443 由 SSL 设置统一管理。

目录不存在时部署任务创建。已有非空目录需明确勾选纳管；保留文件，只在 PHP/托管应用中调整根目录所有者，子文件权限不递归改写。无法访问的既有文件需要在文件管理中核对所有者和权限。旧站点根目录原样保留，编辑域名不会搬动目录。删除站点默认保留项目文件。

## 进程托管

应用端口为 1024–65535，默认由 Nginx 转发至 `127.0.0.1:端口`。应用应配置为仅监听本机；面板不自动开放此应用端口。环境变量使用 JSON 对象，健康检查为同一端口的本机 HTTP 地址。程序必须支持前台运行。开机启动可关闭，异常退出采用有限 systemd 重启策略。

程序配置更新先检查端口、用户及可执行文件，启动后进行端口和可选 HTTP 检查。进程或后续网站配置失败会恢复原服务配置与原启动状态。站点停用、到期会停止专属服务并取消开机启动；延长到期时间后需显式恢复网站。旧外部应用不受此逻辑影响。

此功能位于网站内，不提供独立应用进程菜单。通用旧 `/apps` API 仍拒绝写入，已有历史服务保留。应用日志在网站设置的“应用进程”查看。备份归档实际项目目录，不包含 systemd 服务运行内存，也不等同于应用一致性备份。

## 顶部工具

- **高级设置**：打开当前 Nginx 实例的通用设置，配置更改遵循校验、历史与回退流程。
- **网站统计**：从真实结构化访问日志读取所有受管站点今日响应字节，显示采集失败；单站详情保留小时、7 日和 30 日统计。
- **漏洞扫描**：当前是本机基础检查，显示检查时间、证书、配置漂移、常见敏感条目、目录权限和响应头。只检查项目根目录的固定常见文件名，不读取内容或执行漏洞利用；不包含 CVE 匹配、代码审计或远程扫描，结果不等同于网站没有漏洞。
- **网站安全**：按站点启用 `nosniff`、Referrer-Policy、SAMEORIGIN；PHP 可禁止 `/upload`、`/uploads`、`/storage` 下 PHP 执行。静态/PHP 站点默认拒绝隐藏文件及 SQL、备份、配置、日志后缀文件访问。变更先确认业务影响，再创建应用任务。
- **Nginx 菜单**：对当前入口执行启动、停止、重启或平滑重载。重启与停止可能中断所有关联网站，确认框展示数量。停止 Nginx 不停止面板。

## SSL

创建时可上传 PEM 证书链与私钥，执行器检查域名及密钥匹配后部署。免费证书在建站后的 SSL 设置申请：域名解析指向服务器，HTTP-01 入口需监听并可从公网访问 80，填写邮箱并同意 CA 条款。申请失败保留现有证书。已有 ACME 自动续期流程继续生效。

## 接口与兼容

新建使用 `POST /api/v1/sites`，返回站点、可选数据库关联与任务 ID；设置使用 `POST /api/v1/sites/{id}/settings`，携带修订号，成功应用后才提交元数据。旧资源 API 编辑保存加密草稿，再 apply 进入配置验证流程。`rootDirectory` 是新站点目录请求；`documentRoot`/`runningRoot` 由执行器生成，客户端不能伪造或借编辑迁移已有站点。

只读 `/api/v1/sites/{id}/security` 和 `/api/v1/sites/{id}/process-logs` 响应 `Cache-Control: no-store`。耗时变更沿用任务 API/SSE。SQLite schema 增量升至 6。容器 Nginx 旧挂载保持原样，新项目使用原生入口。

## rc.26 分类、数据库与统一设置

PHP 版本提供“静态”，未安装 PHP 仍可创建静态站。原有静态站点保留 ID 和目录，统一在 PHP 项目显示；其他项目展示托管进程及历史外部应用。创建弹窗不再展示高级设置或 Nginx 选择，自动绑定唯一入口。首个域名生成默认建站目录下的项目文件夹，手改后不再自动覆盖；默认建站目录支持设置中的自定义路径，仍拒绝系统和私有目录。

三类项目共享分类，默认“默认分类”；支持新增、改名、删除和列表筛选。删除分类保留网站。新建默认不创建数据库，也可选择可用 MySQL/PostgreSQL 实例，填写库名、专用账号、密码及编码；默认仅本机访问。凭据不进入站点配置与通用日志。

数据库与站点使用一个编排任务。数据库成功、后续失败时保留并在重试时复用；不确定的中断现场需要核对，不覆盖已有账号。域名与“设置”打开同一固定头尾弹窗，原编辑字段移入对应分区；保存冲突或应用失败保留草稿，退出及切分区检查未保存内容。

Nginx 只允许一个受管实例。版本替换保留实例 ID 和全部站点关联，暂存目标包、全站校验后才进入维护窗口，失败恢复旧运行包。历史多实例先核对合并，不自动停止或删除。

首次创建仅为缺失文件生成响应式首页与 404 模板，不覆盖已有文件。普通静态站返回真正的 HTTP 404；显式 SPA 保留回退，代理保留上游错误。PHP 切为静态时停用独立 FPM，并拒绝下载 PHP/PHTML/PHAR 源文件；切回 PHP 必须通过配置与访问校验。


## rc.30 设置导航与域名

刷新位于搜索旁；域名设置采用多行添加与绑定列表。添加/解除等待真实应用结果，成功后更新绑定表并保持当前弹窗；失败保留输入与原运行配置。链接使用新标签打开，域名加端口作为绑定标识，主域名保留以保证创建目录和探测关联。子目录绑定使用独立域名与根目录下的安全相对路径，拒绝符号链接与隐藏路径。HTTPS 下同名不同端口共用一个证书入口，不允许同名指向不同目录。

结构化策略包含 BasicAuth、目录/后缀/IP 限制、并发/请求限速、路径代理/重定向、防盗链、压缩、静态浏览器缓存、响应头及 CORS。策略通过任务执行 Nginx 检查、重载和修订探测；高级参数保持白名单，完整配置与历史只读核对。BasicAuth 使用 bcrypt 哈希，变更代际文件不会覆盖仍被旧工作进程使用的密码文件。PHP 目录隔离使用独立 FPM 的 open_basedir，Session 隔离沿用原服务。

双向认证先部署 HTTPS，再上传客户端 CA **公共证书**。TLS 请求证书并在业务请求阶段要求验证成功，无证书返回 403；HTTP 业务请求同样拒绝，内部随机健康检查和 ACME 验证入口例外。CA 不包含私钥，不提供撤销服务；需自行管理证书发放、有效期和 CA 更换。

访问/错误日志分别读取；关闭访问日志会停止后续日流量采集，已有统计保留。网站告警使用现有渠道，支持可用性和证书到期；真实公网探测受 DNS、端口、安全策略及客户端认证影响。内核防篡改和专业查杀依赖独立执行器；配额、WebDAV、Composer/Tomcat 未作为已实现功能开放。详见 [菜单映射与验收](website-settings-rc30.md)。
