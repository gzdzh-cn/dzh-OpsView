# 网站创建与管理

## 添加网站

网站菜单保留 PHP 项目、反向代理、其他项目三个标签。安装原生 Nginx 后，点击当前标签的添加按钮。

- **PHP 项目**：每行填写一个域名，选择已安装 PHP 版本，确认根目录、备注及 Nginx 入口。每站使用独立 FPM 服务及非 root 用户。
- **反向代理**：填写域名、HTTP/HTTPS 目标及发送 Host。Host 可用 `$host`、`$http_host`、`$proxy_host` 或指定域名；需要按目标应用配置。高级设置支持多上游、路径、WebSocket 和超时。
- **其他项目 / 托管应用**：先安装运行时或上传可执行构建产物，选择执行文件和 JSON 参数，例如 `/usr/bin/node` 配合 `["server.js"]`。工作目录为项目根目录。默认创建独立用户，也可选择 www-data；不使用 root 或面板用户、不通过 Shell 拼接执行命令。
- **其他项目 / 静态网站**：选择静态网站，部署 HTML/CSS/JS；高级设置支持运行子目录、默认文档及 SPA 回退。

输入首个域名会生成项目名称及 `/www/wwwroot/域名`；修改名称或根目录后继续输入域名不会覆盖手动值。根目录仅支持 `/www/wwwroot` 下的独立文件夹，不允许链接、目录跳转或两个站点共用目录。域名使用 ASCII/Punycode，不附端口、协议或路径，入口端口来自 Nginx 实例。

目录不存在时部署任务创建。已有非空目录需明确勾选纳管；保留文件，只在 PHP/托管应用中调整根目录所有者，子文件权限不递归改写。无法访问的既有文件需要在文件管理中核对所有者和权限。旧站点根目录原样保留，编辑域名不会搬动目录。删除站点默认保留项目文件。

## 进程托管

应用端口为 1024–65535，默认由 Nginx 转发至 `127.0.0.1:端口`。应用应配置为仅监听本机；面板不自动开放此应用端口。环境变量使用 JSON 对象，健康检查为同一端口的本机 HTTP 地址。程序必须支持前台运行。开机启动可关闭，异常退出采用有限 systemd 重启策略。

程序配置更新先检查端口、用户及可执行文件，启动后进行端口和可选 HTTP 检查。进程或后续网站配置失败会恢复原服务配置与原启动状态。站点停用、到期会停止专属服务并取消开机启动；延长到期时间后需显式恢复网站。旧外部应用不受此逻辑影响。

此功能位于网站内，不提供独立应用进程菜单。通用旧 `/apps` API 仍拒绝写入，已有历史服务保留。应用日志在网站设置的“应用进程”查看。备份归档实际项目目录，不包含 systemd 服务运行内存，也不等同于应用一致性备份。

## 顶部工具

- **高级设置**：打开当前 Nginx 实例的通用设置，配置更改遵循校验、历史与回退流程。
- **网站统计**：从真实结构化访问日志读取所有受管站点今日响应字节，显示采集失败；单站详情保留小时、7 日和 30 日统计。
- **漏洞扫描**：当前是本机基础检查，显示检查时间、证书、配置漂移、常见敏感条目、目录权限和响应头。只检查项目根目录的固定常见文件名，不读取内容或执行漏洞利用；不包含 CVE 匹配、代码审计或远程扫描，结果不等同于网站没有漏洞。
- **网站安全**：按站点启用 `nosniff`、Referrer-Policy、SAMEORIGIN；PHP 可禁止 `/upload`、`/uploads`、`/storage` 下 PHP 执行。静态/PHP 站点默认拒绝隐藏文件及 SQL、备份、配置、日志后缀文件访问。变更先确认业务影响，再创建应用任务。
- **Nginx 菜单**：选择实例，执行启动、停止、重启或平滑重载。重启与停止可能中断所有关联网站，确认框展示数量。停止 Nginx 不停止面板。

## SSL

创建时可上传 PEM 证书链与私钥，执行器检查域名及密钥匹配后部署。免费证书在建站后的 SSL 设置申请：域名解析指向服务器，HTTP-01 入口需监听并可从公网访问 80，填写邮箱并同意 CA 条款。申请失败保留现有证书。已有 ACME 自动续期流程继续生效。

## 接口与兼容

新建和编辑仍使用资源 API，`rootDirectory` 是新站点目录请求；`documentRoot`/`runningRoot` 由执行器生成，客户端不能伪造或借编辑迁移已有站点。`type=managed` 表示网站内托管进程，默认其他类型维持兼容。

新增只读 `/api/v1/sites/{id}/security` 和 `/api/v1/sites/{id}/process-logs`，响应 `Cache-Control: no-store`。配置及服务更改使用原任务 API/SSE。SQLite schema 不变化。容器 Nginx 旧挂载保持原样，新 `/www/wwwroot` 项目需使用原生入口。
