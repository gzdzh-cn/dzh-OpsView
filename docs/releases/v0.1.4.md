# OpsView v0.1.4

本版完善“其他项目”的运行用户、权限整理、服务运行限制、端口放行和账号回收生命周期，保持 SQLite schema 6，无新增迁移。正式 Release 设为 GitHub latest，默认安装和 `ov update` 无需指定版本。

- 独立用户（默认）、www-data、可搜索的已有普通用户及受限 root；显示实际主组和来源，拒绝面板账号和 UID 0 别名。
- root 执行配置变更重新验证管理员密码及已启用的 TOTP；授权由服务端绑定站点与摘要，旧接口不能绕过。
- 新托管项目递归整理所有者、访问权限及 Nginx ACL，保留执行位；先检查链接、硬链接、挂载边界和目录依赖。旧项目仅手动“检查与整改”生效。
- 每个服务使用独立挂载空间和最小根目录，仅暴露项目与运行依赖；禁提权、空 capabilities、私有临时目录，屏蔽其他站点和私有数据。普通用户、共享用户和 root 均保留运行限制。
- 其他项目首次创建隐藏 SSL/数据库；端口旁提供默认关闭的“放行端口”，复用现有防火墙，不修改云安全组或监听地址，保留外部/共享规则。
- 账号、权限和服务事务持久化；失败/中断核对并恢复；文件保留、回收和恢复保留用户，彻底清理后仅清理身份未变且无依赖的面板专属用户/组。

## 安装与更新

```bash
curl -fL --retry 3 -o install_opsview.sh https://github.com/gzdzh-cn/dzh-OpsView/releases/latest/download/install.sh && bash install_opsview.sh
```

已有安装先执行 `ov backup` 并独立保管密钥，然后 `ov update`；固定版本可用 `ov update --version v0.1.4`。更新会安装 ACL 基础依赖，不自动整改已有项目或升级业务软件，不重置管理员。

## 运行要求与边界

支持 Linux amd64、Ubuntu 22.04/24.04、Debian 12/13。托管项目要求 systemd ≥249、ACL 与挂载命名空间；不具备能力时明确失败。受限服务不暴露宿主 `/proc`、任意 Unix Socket 或跨站目录；依赖这些路径的应用需事先适配。共享身份和 root 仍不能称为完整主机级隔离。PHP 现有 FPM 策略保留，本版运行限制用于其他项目内的受管进程。

## 验证与回退

本地验证包括 Go/race/vet、前端单元及类型检查、生产构建、浏览器回归，以及隔离 Ubuntu/systemd 上的真实进程、ACL、读路径限制、失败/中断回退和账号回收。公开发布前仍由发布流水线执行 Linux、真实数据库/防火墙、安装更新及实际发布包验收；以 Actions 结果为准，公开 latest 安装和无版本更新在发布后验证。

升级前备份面板数据、执行器状态及 `site-users` 元数据、配置、密钥、systemd 单元和已有权限状态。旧项目不会自动改权。若在新版已手动整改或创建项目，程序快照不能自动还原业务权限/账号/防火墙；先停受影响服务，核对权限事务及关联规则，再恢复同一次快照的程序、元数据、运行配置、密钥和服务单元。不可只替换旧二进制。安装更新失败按更新器配套快照回退，不覆盖网站或数据库业务数据。
